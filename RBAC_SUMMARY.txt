🎯 HOW IT WORKS
═══════════════════════════════════════════════════════════════════════════

BEFORE RBAC:
  User Login → Stored username only → GET /api/warehouses → ALL 4 warehouses

AFTER RBAC:
  User Login → Stored full user object with ID
  → GET /api/warehouses?userId=<id> 
  → Middleware extracts userId
  → Backend filters: WHERE warehouse IN user.warehouses
  → Returns ONLY assigned warehouses


👥 USER TYPES & PERMISSIONS
═══════════════════════════════════════════════════════════════════════════

1. ADMIN USER
   • warehouses: []
   • Sees: ALL warehouses, transfers, analytics
   • Can: Create/edit/delete anything
   • Logic: Empty array = admin privilege

2. WAREHOUSE MANAGER
   • warehouses: ["Warehouse-A"]
   • Sees: Only Warehouse-A
   • Cannot: See other warehouses or create new ones
   • Can: Manage inventory in assigned warehouse

3. RECEPTION AGENT
   • warehouses: ["Warehouse-A", "Warehouse-B"]
   • Sees: Both warehouses and transfers between them
   • Can: Receive transfers, update statuses
   • Cannot: Access other warehouses


🔄 DATA FLOW
═══════════════════════════════════════════════════════════════════════════

Frontend (React)
  └─→ User logs in with email/password
      └─→ Gets: {id, name, email, roles, warehouses}
          └─→ Stored in localStorage

API Calls
  └─→ All GET requests: ?userId=<id>
      └─→ All POST/PUT/DELETE: X-User-ID header
          └─→ Automatic in api.js (no component changes)

Backend Middleware
  └─→ Extract userId
      └─→ Fetch user from database
          └─→ Populate req.user
              └─→ Route handlers check permissions

Route Handlers
  └─→ Check if user is admin
      └─→ If not admin: apply warehouse/transfer filters
          └─→ Execute query with filters
              └─→ Return only authorized data

Database
  └─→ Only rows matching user's warehouses
